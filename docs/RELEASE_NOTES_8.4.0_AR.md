# OUSSAMA Cutter 8.4.0-ultimate — حلقة الأداء المغلقة

_التاريخ: 2026-11-13 · النطاق: التعلّم من نتائج النشر، عدالة القياس، والتحديث التلقائي_

## 1. لماذا

كانت الحلقة موجودة شكلياً: `publish_history` → YouTube Analytics →
`performance_insights.json` → أوزان الاختيار. لكن القياس كان يخدع نفسه:

- **نافذة 365 يوماً**: مقطع عمره 300 يوم يجمع مشاهدات 300 يوم، وجديد 10 أيام
  يجمع 10. التعلّم كان يقيس العمر لا الجودة.
- **Pearson على المشاهدات الخام**: مقطع واحد بمليون مشاهدة يقلب إشارة خاصية
  محايدة في كل المقاطع الأخرى.
- **لا احتفاظ**: كنا نعرف المشاهدات ولا نعرف هل بقي المشاهد أم غادر.
- **تحديث يدوي**: لا شيء يعيد الاستعلام بعد الرفع.
- **عينة صغيرة تتحرك بقوة**: 3 مقاطع كانت تحرك الأوزان كما لو كانت 30.

## 2. القياس العادل

- كل المقاطع تُقاس داخل **نفس النافذة** (28 يوماً افتراضياً).
  `VIRALCUTTER_PERF_WINDOW_DAYS` يضبطها بين 7 و365.
- التقرير يذكر النافذة وطريقة الارتباط صراحةً.

## 3. ارتباط رتبي

- `_spearman` بدل Pearson: يسأل «هل المقاطع الأعلى تقييماً ترتّب أعلى؟»
  لا «هل مقطع واحد يطغى على الباقي؟».
- يتعامل مع القيم المتساوية (average ranks).
- `method: "spearman"` في كل ارتباط، مع `samples` و`retention_samples`.

## 4. الاحتفاظ والمشاهدون

- `averageViewPercentage` و`subscribersGained` يُجلبان مع المشاهدات.
- كل خاصية لها `vs_views` و`vs_retention`.
- دروس المحتوى (hook_type، angle، topic، نمط العنوان) تحمل الآن
  `avg_retention` و`delta_retention_pct`، لا المشاهدات فقط.

## 5. ثقة حسب حجم العينة

- `confidence = min(1, n/5)`: عند 5 مقاطع مقاسة أو أكثر تتحرك الأوزان بكامل
  قوتها؛ عند 3–4 تتحرك بنسبة 60–80% فقط.
- التقرير يذكر `needed_samples` (كم مقطعاً إضافياً للثقة الكاملة).
- السقوف السابقة باقية: لا إزاحة أكبر من 0.10، والنمط لا يزيد عن 3 نقاط، ومكافآت الأنماط تنكمش بنفس الثقة (3 مقاطع = 60%).

## 6. تحديث تلقائي

- `performance_loop.auto_refresh`:
  - يتخطى إن كان التقرير أحدث من سجل النشر وأقل من 6 ساعات
    (`VIRALCUTTER_PERF_REFRESH_HOURS`).
  - بعد رفع ناجح يكتب `performance_refresh_due.json`، فيتجاوز الـTTL مرة واحدة.
  - **لا يستبدل تقريراً فيه أرقام بتقرير فارغ** إذا فشل OAuth/الشبكة؛
    يحتفظ بالنسخة الجيدة ويقول `kept_previous_metrics`.
- `python -m scripts.performance_loop --project X --auto [--force]`.
- زر «تحليل الأداء» في الواجهة يستخدم التحديث التلقائي ويعرض السبب.

## 7. تقرير قابل للقراءة

بجانب JSON يُكتب `performance_insights.md`:

- النافذة، عدد المنشور/المقاس، طريقة الارتباط.
- جدول ارتباط views/retention لكل خاصية.
- ما ينجح على القناة (بالمشاهدات والاحتفاظ).
- أفضل ساعات النشر.
- **ما تغيّر في الاختيار** و**التوصيات للجولة القادمة** بلغة تنفيذية:
  «ارفع وزن hook»، «فضّل مقاطع أقصر»، إلخ.

## 8. التشغيل

```bash

# فرض استعلام جديد بعد رفع دفعة
python -m scripts.performance_loop --project "VIRALS/my_project" --auto --force

# بلا شبكة (تحليل محلي فقط)
python -m scripts.performance_loop --project "VIRALS/my_project" --offline
```
