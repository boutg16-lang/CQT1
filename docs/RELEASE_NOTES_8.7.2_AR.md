# OUSSAMA Cutter 8.7.2-ultimate — تفريغ طويل بلا OOM

_التاريخ: 2026-11-14 · النطاق: تقسيم الصوت إلى نوافذ قبل faster-whisper_

## 1. العَرَض

```
Unable to allocate 383. MiB for an array with shape (1, 174490, 576) float32
[oom-guard] OOM with 'base' — falling back to 'tiny'
Unable to allocate 341. MiB for an array with shape (89338776,)
[oom-guard] OOM even on 'tiny' — giving up
```

الرسالة ليست 403 يوتيوب؛ التلميح القديم كان يخدع. المشكلة أن faster-whisper
(وWhisperX) يحسب **مصفوفة ميل لكامل الصوت** قبل التفريغ:
`174490` إطاراً ≈ 29 دقيقة. حتى النموذج الصغير لا ينجو لأن المشكلة في
المصفوفة لا في النموذج.

## 2. الحل

### تقسيم تلقائي إلى نوافذ
`transcription_fallback.transcribe` الآن:

1. يقيس مدة الصوت بـ`ffprobe`.
2. إذا تجاوزت النافذة (افتراضي **300 ثانية**)، يقسّم الصوت بـ`ffmpeg`
   إلى WAV أحادي 16 kHz.
3. يفرّغ كل نافذة على حدة بنفس النموذج المحمّل (لا إعادة تحميل).
4. يزيح `start/end` لكل مقطع وكل كلمة بمقدار بداية النافذة.
5. يدمج المقاطع ويرتبها، ويعيد استخدام اللغة المكتشفة في النوافذ التالية.
6. يحذف ملفات النوافذ المؤقتة دائماً.

النتيجة: الذاكرة تتناسب مع **النافذة** لا مع الفيديو كله:
- 29 دقيقة → 6 نوافذ × ~65 MiB بدل 383 MiB دفعة واحدة.
- فيديو قصير (≤ 5 دقائق) → مسار واحد كما كان، بلا تقسيم.

### تحكم
```powershell
# نافذة أصغر لأجهزة الذاكرة المحدودة
$env:VIRALCUTTER_TRANSCRIBE_CHUNK_SECONDS = "180"
```
النطاق المسموح 60–900 ثانية؛ الافتراضي 300.

### رسائل صحيحة
- `Unable to allocate` / `out of memory` صار تلميحها «الذاكرة غير كافية»
  قبل تلميح يوتيوب 403.
- `build_error_message` يشرح أن CQT1 يقسم الصوت تلقائياً، ولا يطلب إعادة
  تثبيت الحزم بسبب OOM.

## 3. ماذا تفعل الآن

```powershell
cd D:\OS
git pull
.\run_webui.bat
```

- اختر `large-v3` أو `large-v3-turbo` كالمعتاد.
- لا تحتاج إلى `small` أو `tiny` بعد الآن، إلا إذا كانت الذاكرة الحرة
  أقل من ~200 MiB.
- إن كانت الذاكرة ضيقة جداً:
  ```powershell
  $env:VIRALCUTTER_TRANSCRIBE_CHUNK_SECONDS = "120"
  ```

## 4. التحقق

- `tests/test_transcription_chunking.py` — 3 اختبارات:
  - حدود حجم النافذة.
  - إزاحة المقاطع والكلمات عبر نافذتين.
  - الصوت القصير يبقى بمسار واحد.
- `tests/test_webui_utils.py` — اختبار: OOM يتفوق على تلميح 403.
- المجموعة كاملة خضراء، `ruff` نظيف.

## 5. حدود

- التقسيم بلا تداخل؛ قد تُقطع كلمة عند حد النافذة نادراً. الحدود كل 5
  دقائق، والأثر محدود.
- كل نافذة تُفرَّغ تسلسلياً؛ الزمن الكلي مشابه، والذاكرة أقل بكثير.
- إن كان النموذج نفسه لا يتسع في RAM (وليس المصفوفة)، استخدم
  `small`/`medium` أو أغلق البرامج الثقيلة.
