# ملاحظات إصدار OUSSAMA Cutter 7.14.0-pro

**تاريخ الإصدار:** 22 أغسطس 2026

## ما الذي تغير

تعالج هذه النسخة المشكلة التي كان فيها التحسين الاحترافي يعمل أحياناً ثم تظهر نسخة أصلية أو fallback وكأنها محسّنة. أصبح كل مقطع يملك تقريراً مستقلاً داخل `polish_report.json` يوضح المراحل المطلوبة والمطبقة والمتخطاة والفاشلة، وحالة الجودة `enhanced` أو `partial` أو `fallback` أو `failed`. المخرج يُنسخ أو يُنقل بشكل ذري بعد التحقق من الحجم والمدة، ولا يُنقل المصدر الأصلي بالخطأ عندما لا تنتج مرحلة transform.

تم إصلاح نجاح branding الكاذب عند فقدان الشعار أو فشل ffmpeg. غياب asset اختياري يُسجل كتخطٍ طبيعي، أما asset اختاره المستخدم ثم فشل تطبيقه فيُسجل كفشل واضح. كما أصبحت رسائل main pipeline تفرق بين المقطع المحسن، الجزئي، fallback، والفاشل.

أعيد بناء الرفع الدفعي ليعالج كل الملفات النهائية بالتتابع ويحفظ `publish_batch_report.json` بعد كل ملف. الحالات المدعومة هي `uploaded` و`scheduled` و`dry_run` و`skipped_duplicate` و`blocked` و`failed`. لا تعرض الواجهة رسالة نجاح شاملة إذا فشل عنصر. ويمكن إعادة استدعاء الدفعة مع `retry_failed_only=True` لمعالجة الملفات الفاشلة فقط، بينما يحمي سجل البصمة الملفات الناجحة من إعادة الرفع.

عند تحديد وقت البداية، يُحسب وقت مستقل لكل ملف: وقت المقطع التالي يساوي وقت البداية مضافاً إليه الفاصل بالدقائق. يدعم المسار أكثر من خمسة مقاطع، ويرفض الوقت غير المرفق بمنطقة زمنية أو الفاصل خارج 1 إلى 10080 دقيقة قبل أي رفع.

أضيف `prepare_youtube_preflight` قبل التفريغ والقص. يتحقق من وجود ملف OAuth صالح، ويخزن الملف المحدد بأمان، ويلغي التوكن القديم عند تغيير client secrets، ويتحقق من صلاحية التوكن والقناة وقاطع مخاطر القناة وخصوصية `private` عند الجدولة. لا يفتح OAuth تفاعلياً ولا يرفع أثناء preflight، ولا يدّعي إمكانية معرفة quota الحقيقية قبل طلب الرفع.

## سلوك الأمان

يظل `Dry Run` هو الوضع الافتراضي ولا يسجل نجاحاً في سجل النشر. الرفع الفعلي يحتاج اختياراً صريحاً من المستخدم، وتبقى بوابة الأمان ومنع التكرار وقاطع القناة مفعلة. لا يسمح النظام بالنشر العام الحقيقي دون تأكيد Public، ولا يرفع مخرج `final_polished` صُنّف fallback أو failed أو invalid في تقرير polish.

هذه الحواجز تقلل المخاطر ولا تضمن قبول YouTube أو تمنع كل قرار إنفاذ؛ يجب استخدام فيديو يملكه المستخدم أو يملك حق نشره، ومراجعة السياق والعنوان والوصف قبل النشر. لا توجد في هذه النسخة أي محاولة للتحايل على Content ID أو أنظمة المنصة.

## الملفات المهمة

| الغرض | الملف |
|---|---|
| تقرير التحسين لكل المشروع | `polish_report.json` |
| تقرير كل دفعة رفع | `publish_batch_report.json` |
| سجل الأحداث والبصمات | `publish_history.jsonl` |
| تقرير الجاهزية | `project_report.json` و`project_report.html` |
| تحقق YouTube قبل المعالجة | `webui/app.py: prepare_youtube_preflight` |
| الرفع المنظم والاستئناف | `webui/publish_panel.py` |

## الاختبارات

اجتازت النسخة اختبارات `pytest -q` و`ruff check .` و`python -m compileall -q .` في بيئة الخادم. لا تشمل هذه الاختبارات تسجيل دخول Google أو رفعاً حقيقياً أو فحص CUDA فعلياً على Windows؛ يجب تنفيذ قبول Windows على جهاز المستخدم وفق `docs/RELEASE_CHECKLIST_WINDOWS.md`.
