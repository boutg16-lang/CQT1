# التقرير النهائي لمشروع OUSSAMA Cutter

**الإصدار:** 7.26.0-pro
**تاريخ التحديث:** 27 أغسطس 2026
**الحالة:** إصدار مهني مرشح للتسليم؛ اجتاز اختبارات المصدر وWebUI المحلية وطبقة Telegram المحاكية، بينما يبقى اختبار Torch/CUDA وTelegram وYouTube الحقيقي على جهاز Windows RTX 3060 خطوة تشغيلية لا يمكن تنفيذها من خادم Linux.

## الملخص التنفيذي

أصبح **OUSSAMA Cutter** منصة إنتاج متكاملة لتحويل الفيديو الطويل إلى مقاطع قصيرة قابلة للمراجعة والتحرير والنشر، لا مجرد أداة قص. تركز هذه الدفعة على الاعتمادية بعد الانقطاع، منع التكرار، الحواجز الآمنة للنشر، تشخيص Windows، تنظيم الواجهة العربية، والتعلم من نتائج التشغيل دون تسريب الأسرار أو إجبار المستخدم على تسجيل الدخول.

> **قاعدة الأمان الأساسية:** لا يبدأ الفحص الآمن أي تنزيل أو OAuth أو رفع حقيقي. ويظل `Dry Run` هو الوضع الافتراضي في مسار النشر، بينما يتطلب `Public` الحقيقي تأكيداً صريحاً داخل الواجهة ويمر دائماً عبر بوابة السلامة ومنع التكرار.

## ما تم تطويره في 7.26.0-pro

تضيف هذه الدفعة فحص جودة صوت محلياً بعد اكتمال المخرجات، باستخدام `loudnorm` و`silencedetect` من FFmpeg. ينشئ `audio_qc_report.json` بحالة `pass` أو `review` أو `block` ويعرضها في `project_report.json` و`project_report.html` وواجهة تدقيق الجاهزية. تستمر المعالجة المحلية في الوضع التحذيري، لكن الرفع الحقيقي يرفض الملف غير الناجح قبل OAuth أو YouTube API. عند إعادة القص يُمسح التقرير القديم مع artifacts اللاحقة.

## ما تم تطويره في 7.25.1-pro

تحافظ هذه الدفعة على حماية إعادة النشر والتداخل والمحتوى الخطر ومركز Telegram المحلي المضافين في 7.24، وتضيف مسار تفريغ مستقلّاً عبر faster-whisper لمعالجة تعطل WhisperX أو Torch، مع اختيار backend صريح وتشخيص وتثبيت اختياري على Windows. لا يُستخدم fallback لتجاوز بوابة السلامة أو لتمرير ترجمة وهمية إلى الإنتاج.

يعالج hotfix 7.25.1 حالة شائعة عند استئناف مشروع قديم: إذا احتوت ملفات SRT أو TSV أو JSON على cues ذات timestamps لكن بلا نص، تُزال هذه الصفوف الفارغة كتابةً ذرية قبل التحقق. وإذا بقيت timestamps تالفة أو فشل التحقق مع checkpoint مكتمل، يمسح OUSSAMA marker التفريغ والـcache ويعيد التفريغ مرة واحدة فقط، ثم يوقف المرحلة بأمان إذا بقيت النتيجة غير صالحة.

## سير العمل الموصى به

يختار المستخدم رابط YouTube أو فيديو محلياً أو مشروعاً موجوداً. الفيديو المحلي يُستخدم من مساره ولا يُنسخ مرة أخرى إلى `VIRALS`. بعد ذلك يعرض زر فحص الإعدادات الأخطاء قبل أي اتصال خارجي، ثم تمر المعالجة عبر التفريغ والاختيار والحارس الآلي للمصدر والسياسة والقص والترجمة والفحص الدلالي والبصري عند تفعيله والتحقق النهائي.

قبل الرفع، يجب اختيار قناة YouTube والتحقق منها من تبويب النشر أو تفعيل الحاجز المطلوب قبل المعالجة. يثبت preflight القناة والاعتماد وقاطع المخاطر ووقت الجدولة قبل بدء التقطيع؛ تغيير `client_secrets.json` يلغي التوكن القديم ويطلب ربطاً جديداً. يحدد المستخدم مصدر الملفات من `final_polished` أو `final` أو `cuts` أو ملف MP4 محدد. يبدأ الاختبار بوضع Dry Run، ثم يمكن إلغاؤه بعد مراجعة التقرير. عند وجود polish_report متدهور، لا يختار المصدر التلقائي `final_polished`، ولا يُسمح برفعه الحقيقي عند اختياره صراحة. لا يُسمح بـPublic الحقيقي إلا مع تأكيد صريح، ولا يُقبل مقطع محظور أو يحتاج مراجعة يدوية.

## الاعتمادية والاستئناف

يحافظ checkpoint على الحقل القديم `stages: {stage: true}` حتى تبقى المشاريع السابقة قابلة للقراءة، ويضيف metadata منفصلة لا تكسر التقرير القديم. تسجل كل مرحلة أحداثاً من نوع start وsuccess وfailure وskip، وتمسح `active_stage` بعد النجاح أو الفشل النهائي مع الاحتفاظ بـ`last_error` للتشخيص. يستطيع المستخدم رؤية هذه الحالة من تقرير المشروع.

يعمل الطابور بملف حالة دائم ويستعيد المهام بعد إعادة تشغيل WebUI. تعالج الأولوية الأعلى أولاً، وتُهمل العناصر التي لم تعد في حالة queued أو retrying إذا ظهرت نسخة قديمة في بنية الأولوية. هذه السياسة تمنع تشغيل المهمة نفسها بعد الإلغاء أو الاستئناف أكثر من مرة.

## الأمان والمحتوى الحساس

يطبق المشروع طبقات متتابعة تشمل فلتر الكلمات، التحليل الدلالي، حارساً آلياً للمصدر والتكرار، بطاقة المخاطر، الفحص البصري المحلي عند توفر نموذج ONNX، والتحقق النهائي قبل النشر. في الوضع الآلي، تُحجب حالات `block` و`review` قبل القص بدلاً من إرسالها إلى الرفع. وضع الحظر يوقف المقطع، ووضع censor يخفي الكلمات الصريحة عند إمكان ذلك، بينما يُبقي flag المقطع للمراجعة. لا تُعتبر هذه الآليات ضماناً لقبول YouTube أو بديلاً عن المراجعة البشرية، خصوصاً للمحتوى السياسي أو الديني أو الذي قد يُفهم خارج سياقه.

## YouTube والنشر الآمن

يستخدم التكامل OAuth محلياً مع `client_secrets.json` الذي يختاره المستخدم من جهازه. يُحفظ الملف والتوكن في مخزن خاص ولا يُطبع محتواهما في السجل. عند استبدال client secrets يُبطل التوكن القديم لتجنب استخدام اعتماد مرتبط بتطبيق مختلف. وعند ظهور نقص في النطاقات، تظهر تعليمات إعادة الربط بدلاً من إعادة المحاولة العمياء.

يسجل كل حدث رفع بصمة الملف، والمنصة، والخصوصية، والجدولة، والعنوان، والحالة، ومعرّف الفيديو أو الرابط عند النجاح. في الدفعات، يُحفظ `publish_batch_report.json` بعد كل ملف، ويُفرّق الملخص بين uploaded وscheduled وdry_run وskipped_duplicate وblocked وfailed. إذا فشل عنصر، يمكن تشغيل retry للفاشل فقط؛ أما العناصر الناجحة فتُحمى بالسجل والبصمة ولا تُعاد. كما يسجل `content_guard` المصدر ونافذة المقطع والقرار. إذا كانت نافذة المصدر نفسها أو البصمة نفسها قد نُشرت سابقاً، يُمنع المرشح قبل القص أو الرفع حسب المرحلة. أما Dry Run فلا يُعامل كنجاح سابق ولا يمنع الاختبار اللاحق.

## Windows وRTX 3060

يجب تشغيل البيئة على قرص يملك مساحة كافية، ويفضل أن يكون المشروع و`TEMP` وcache الخاصة بـuv على `D:` لتجنب امتلاء `C:` أثناء استخراج Torch وnumpy. يستخدم الجهاز الذي يملك NVIDIA خيار CUDA، بينما يعمل CPU كبديل أبطأ. لا يكفي وجود بطاقة RTX في النظام؛ يجب أن يعرض التشخيص `torch.cuda.is_available() = True` عند اختيار GPU وأن يظهر اسم RTX 3060. يكفي للعمل الاحتياطي نجاح استيراد faster-whisper، ويمكن تشغيله على CPU إذا لم تتوفر مكتبات CUDA المناسبة.

يشغل المستخدم من PowerShell:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
cd D:\SS
.\setup_on_d.ps1 -Mode Full -Transcription gpu
.\.venv\Scripts\python.exe -m scripts.windows_diagnostics --json --output windows_diagnostics.json
Get-Content .\windows_diagnostics.json
# عند تعطل WhisperX فقط، ثبّت fallback المستقل:
.\.venv\Scripts\python.exe -m scripts.transcription_diagnostics --repair-fallback
.\run_webui.bat
```

وللجهاز غير المدعوم بـCUDA:

```powershell
.\setup_on_d.ps1 -Mode Full -Transcription cpu
```

إذا فشل التثبيت بسبب المساحة، يجب تنظيف cache المؤقتة على `C:` أو نقل cache حسب رسائل المثبت، ثم إعادة تشغيل الفحص. لا تُستخدم ترجمة وهمية في الإنتاج الحقيقي.

## Telegram Control Center المحلي

يعمل مركز Telegram اختيارياً داخل عملية OUSSAMA Cutter نفسها باستخدام long polling صادر من Windows. لا يوجد webhook أو منفذ عام، وتبقى ملفات `VIRALS` وOAuth والمعالجة على الجهاز. لا يبدأ المركز إلا مع `VIRALCUTTER_TELEGRAM_ENABLED=1` وBot Token وChat IDs صحيحة؛ الدردشة غير المصرح بها لا تتلقى رداً، وBot Token لا يظهر في WebUI أو السجل أو ZIP.

تعرض الصفحة الرئيسية حالة disabled أو configuration incomplete أو ready وعدد Chat IDs فقط. تدعم الخدمة `/status` و`/projects` و`/audit` والتحكم الآمن بالطابور، ولا تضيف `/upload` أو `/publish` أو بدء pipeline من Telegram. الإلغاء الجماعي يحتاج تأكيداً خلال 60 ثانية. الإشعارات النهائية اختيارية ومغلقة افتراضياً، وتحتوي الحالة ومعرّف المهمة المختصر فقط.

طريقة الإعداد واختبار Windows موثقة في `docs/TELEGRAM_CONTROL_AR.md`، والملف `telegram_control.example.ps1` نموذج بلا Token فعلي. يجب أن ينشئ المستخدم البوت عبر BotFather ويضبط الأسرار محلياً دون إرسالها في المحادثة أو الدعم.

## التحليلات والتعلم

يقدم تبويب الأداء مسارين منفصلين. المسار المحلي يقرأ سجلات المشروع من `publish_history.jsonl` ويعرض عدد الأحداث، النجاح والجدولة، الفشل، Dry Run، تخطي التكرار، الخصوصية، المنصات، والعناوين الناجحة المتكررة. هذا المسار لا يحتاج OAuth ولا يرسل بيانات للخارج. أما مسار YouTube Analytics فيطلب نطاقات القراءة فقط عند اختياره، ويعرض ملخص القناة وأفضل المقاطع والاتجاه اليومي.

تعلم الأداة من سجل الكلمات المحظورة وسجل الرفع هو **مساعدة تحليلية** لا تغيير تلقائي صامت لإعدادات المحتوى. يجب مراجعة أي كلمة أو نمط مستخرج قبل تطبيقه على القائمة النشطة.

## النسخ الاحتياطي والاستعادة

ينشئ زر النسخ الاحتياطي ZIP ذرياً في مجلد يختاره المستخدم. يستبعد الملف تلقائياً `token.json` و`client_secrets.json` والاعتمادات وcache وملفات Python المترجمة والملفات المؤقتة، ويستبعد الوسائط افتراضياً لتقليل الحجم. يمكن تضمين الفيديو والصوت اختيارياً. يفحص النظام manifest ومسارات ZIP لمنع traversal، وتتم الاستعادة دائماً إلى مشروع جديد collision-safe دون الكتابة فوق مشروع موجود.

## حدود مهمة قبل الاستخدام التجاري

الحماية الآلية تقلل المخاطر ولا تمنح ضماناً ضد قرار YouTube؛ لا يستطيع Data API وحده كشف كل إنذارات القناة أو تقييم السياق الكامل. لذلك يُوقف النظام الحالات الخطرة أو الملتبسة، ويجب عدم تحويل ذلك إلى ثقة زائفة أو إلى طريقة لتجاوز أنظمة المنصة.

لم يُنفذ في هذه البيئة أي تسجيل دخول Google أو رفع حقيقي أو تنزيل YouTube أو اختبار Torch CUDA على Windows. يجب تنفيذ تلك الخطوات على جهاز المستخدم بعد مراجعة ملف client secrets وقناة النشر والمحتوى. كما يجب الاحتفاظ بنسخ احتياطية من المشاريع قبل تحديثات كبيرة، وعدم مشاركة أي token أو client secret في الدعم أو GitHub أو الأرشيف.
