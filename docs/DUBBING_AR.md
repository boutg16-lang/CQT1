# الدبلجة متعددة اللغات — `scripts/dubbing.py`

> **الفكرة مأخوذة من MoneyPrinterTurbo (MIT) وأُعيدت كتابتها على مقاسات المشروع.**
> الفجوة التي تسدّها: المشروع يترجم الترجمات منذ زمن (`scripts/translate_json.py`)،
> لكن المقطع يبقى **بصوتك الأصلي** — فلا يمكن نشره لجمهور آخر إلا مترجَماً مكتوباً.

---

## 1) المزوّدون

| المزوّد | الشبكة | الوصف |
|---|---|---|
| `edge` | **نعم** | Microsoft Edge TTS — مجاني وبلا مفتاح API. **يرسل النص إلى مايكروسوفت.** |
| `file` | لا | صوت مسجَّل مسبقاً من مجلد (`--voice <مجلد>`) — بلا شبكة، وللاختبار وللدبلجة بتسجيلك. |

`edge` **مرفوض افتراضياً** ولا يعمل إلا بـ:

```powershell
$env:VIRALCUTTER_TTS_ALLOW_NETWORK=1
```

هذا مسار اختياري لإرسال النص إلى خدمة خارجية. توجد ميزات أخرى تتصل بالإنترنت أيضاً، مثل مزوّدات الذكاء الاصطناعي والنشر؛ راجع [سياسة الأمان وسلوك الشبكة](../SECURITY.md#network-and-data-flow) لمعرفة التفاصيل.

```powershell
python -m scripts.dubbing --providers     # عرض المزوّدين
```

## 2) التشغيل من الواجهة (الأسهل)

في تبويب **🚀 رفع ونشر** ← قسم الترجمة، تجد تحت زر «Translate Subtitles»:

1. **مزوّد الصوت:** `file` (تسجيل محلي بلا شبكة) أو `edge` (يحتاج تفعيل خيار الشبكة).
2. **وضع الصوت:** `replace` (استبدال) أو `mix` (الدبلجة فوق الصوت الأصلي).
3. **الصوت أو مجلد التسجيلات:** مجلد ملفاتك لمزوّد `file`، أو اسم الصوت لمزوّد `edge`.
4. **«السماح بالشبكة»**: مربّع اختياري صريح — بدونه يرفض `edge` العمل.
5. اضغط **🎙️ دبلجة المقطع المترجم**.

الناتج في `final_dubbed/`، وتظهر رسالة تُذكّرك بالإفصاح عن الصوت المُصنَّع.
**الدبلجة لا ترفع شيئاً** — الرفع يبقى من تبويب النشر بنفس بواباته.

## 3) التشغيل من سطر الأوامر

```powershell
# معاينة فقط (بلا توليد صوت)
python -m scripts.dubbing --project VIRALS\my-project --provider file --voice D:\my-voice

# دبلجة كل المقاطع التي لها ترجمة
python -m scripts.dubbing --project VIRALS\my-project --provider edge --voice ar-EG-ShakirNeural

# مقطع واحد، ووضع الخلط (الصوت الأصلي خلفي بدل استبداله)
python -m scripts.dubbing --project VIRALS\my-project --index 0 --mode mix
```

النواتج: `final_dubbed/*_dubbed.mp4` + `dubbing_report.json`.

## 4) كيف يحترم المشروع قواعده

| القاعدة | كيف طُبِّقت |
|---|---|
| **لا يخرج شيء بلا إذن** | مزوّد الشبكة مرفوض بلا `VIRALCUTTER_TTS_ALLOW_NETWORK=1` |
| **الفشل لا يكسر شيئاً (fail-open)** | فشل سطر واحد يُتخطّى ويُسجَّل والصوت الأصلي يبقى تحته؛ فشل كل الأسطر ⇒ لا ملف ناتج والمقطع الأصلي كما هو |
| **لا ملف مقطوع يُنشر** | الناتج يمر `media_validation` قبل تبنّيه، والكتابة ذرّية (`tmp` ثم `os.replace`) |
| **التزامن مع الصورة** | كل سطر يُلائم داخل نافذته الزمنية بـ`atempo` (بحدود 0.5×–3×، والزيادة تُسجَّل كتحذير) |
| **لا دوبلاج صامت** | فحص ذاتي يقيس جهارة المسار الناتج ويحذّر إن كان صامتاً |
| **لا تجاوز للبوابة** | الدبلجة **تكتب ملفات فقط**؛ النشر يمر بنفس `upload_gate`/`content_guard` وDry Run وتأكيد النشر العام. يوجد اختبار يثبّت أن الدبلجة لا تلمس البوابة إطلاقاً |

## 5) إفصاح إلزامي عند النشر

التقرير يحمل دائماً `synthetic_voice: true` و`disclosure_required: true`:

- يوتيوب يطلب **الإفصاح عن المحتوى المُعدَّل/الاصطناعي**.
- المقطع المدبلج **تحويل جوهري** مشروع (يفيدك في `originality`/`provenance`)، لكنه
  **ليس أصلاً جديداً** ولا يُرفع كنسخة مكررة على المنصات.

> هذا الفحص لا يُغني عن المراجعة البشرية: اسمع المقطع المدبلج قبل النشر، خاصة في
> المحتوى الديني/السياسي حيث يغيّر النبر صوت المعنى.
