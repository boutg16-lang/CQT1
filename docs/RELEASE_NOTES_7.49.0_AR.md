## الجديد: إغلاق #25 و#26 بأمر واحد للمالك

إصلاح ملفات الـ workflow كان جاهزاً ومختبَراً منذ 7.45، لكن **لا يمكن دفعه من
حساب الأتمتة** (GitHub يطلب صلاحية `Workflows`). المالك كان يحتاج خطوات يدوية
متعددة وترتيباً حساساً. الآن:

```powershell
cd D:\SS
git pull
python -m scripts.apply_ci_workflow_fix              # تجربة جافة
python -m scripts.apply_ci_workflow_fix --apply --push
```

### ما يفعله الأمر

1. ينسخ `.github/workflows/build-exe.yml` و`ci.yml` من `packaging/ci-fix/`
   (مطابقتان بايت-ببايت للرقعة الموثَّقة في `docs/ISSUE_25_workflow_fix.patch`)،
   **بكتابة LF مباشرة** — فلا مخاطر فشل `git apply` على Windows بسبب CRLF.
2. يزيل الـ shim المؤقت من `packaging/viralcutter.spec` **في نفس العملية** —
   الترتيب الصحيح (إزالة الـ shim قبل تحديث الـ workflow تُسقط البناء).
3. يتحقق قبل الدفع: YAML صالح، وجود `checksums.txt`، تطابق `EXE_NAME` مع اسم
   الـ spec، وإزالة الـ shim فعلاً.
4. `--push` ينشئ commit ويدفعه بصلاحياتك. آمن للتكرار مع أكواد خروج 0/1/2.

### الإصلاحان المضمَّنان

- **#25:** `EXE_NAME` كمصدر واحد، حارس تطابق مع الـ spec يفشل البناء فوراً بدل
  التعليق حتى المهلة، smoke test محصَّن (مهلة 240s + طباعة السجل دائماً +
  كشف الانهيار)، وتوليد `checksums.txt` يُرفق بالـ Release فيعمل `auto_updater`
  المصمَّم fail-closed.
- **#26:** `pytest` قبل رفع الـ artifact في `ci.yml`، وإنشاء الـ Release قبل رفع
  الـ artifact في `build-exe.yml`، و`retention-days: 7` — فحصة التخزين لم تعد
  تُخفي نتيجة الاختبارات ولا تمنع نشر الإصدار.
