# ملاحظات إصدار OUSSAMA Cutter 7.17.0-pro

## شاشة التدقيق قبل الرفع

أضيف إلى تبويب «رفع ونشر» زر **تدقيق جاهزية الرفع قبل البدء**. يعرض التقرير عدد الملفات المتاحة من مصدر الرفع، وعدد segments الحالي، واكتمال الدفعة، وحالة Professional Polish، وbackend المستخدم في تتبع الوجه والمتحدث، وحالة قاطع مخاطر القناة، ثم يتحقق من OAuth والقناة والجدولة عبر preflight آمن.

التدقيق لا يبدأ OAuth تفاعلياً ولا يرفع ملفات. عند تفعيل Dry Run يوضح ذلك صراحةً، وعند اختيار الرفع الحقيقي يعرض أن القرار أصبح فعلياً ويترك التأكيد النهائي للمستخدم. لا يدعي النظام معرفة quota قبل طلب الرفع، لأن أخطاء الحصة قد تظهر لكل مقطع أثناء التنفيذ.

## حماية الدفعة الناقصة

قبل الرفع التلقائي، يقارن النظام عدد ملفات MP4 الصالحة بعدد segments الموجودة في `viral_segments.txt`. إذا كانت الملفات أقل من العدد المتوقع، يتوقف الرفع ويعرض السبب بدلاً من رفع جزء من الدفعة أو إعلان نجاح شامل. يبقى اختيار ملف محدد متاحاً عندما يريد المستخدم رفع ملف واحد يدوياً.

## حماية حالة الطابور

إذا تلف ملف `.batch_queue.json` بسبب انقطاع نادر أو خطأ في التخزين، لا تُحذف الحالة بصمت. يحفظ التطبيق الملف باسم `queue.json.corrupt-<timestamp>` ويسجل تحذيراً في واجهة الطابور، حتى يستطيع المستخدم الاحتفاظ به للتشخيص وبدء طابور نظيف بقرار واضح.

## استمرار حماية المخرجات

تستمر النسخة في تنظيف المخرجات المشتقة القديمة عند إعادة القص، والاعتماد على `cuts_manifest.json`، والتحقق من MP4 عبر ffprobe، وإيقاف المرحلة عند فشل segment أو mux أو إخراج فارغ. كما يستمر منع إعادة job عند تكرار resume، ومنع رفع `final_polished` المتدهور في المسار التلقائي الحقيقي.

## التحقق

نجح regression الكامل بعد هذه التغييرات بعدد **718 اختباراً**، ونجح `ruff check .` و`python3 -m compileall -q .`. تم تشغيل WebUI محلياً والتحقق من ظهور `OUSSAMA Cutter v7.17.0-pro` وتبويب «تدقيق جاهزية الرفع قبل البدء» دون OAuth أو رفع حقيقي.
