# سياسة النشر الآمن — YouTube وTikTok

يمنع المشروع النشر الآلي عندما تكون السلامة أو ملكية المحتوى أو أصالته غير واضحة. لا يوجد تحويل بصري صغير — تغيير السرعة أو قلب الصورة أو القص أو اللون — يضمن قبول المنصة.

## بوابة النشر الفعلي

- قبل الرفع الحقيقي، يجب أن تتوفر تقارير السلامة والمخاطر، وأن تطابق أزمنة المقطع المختار؛ وجود تقارير قديمة أو تخص مقطعاً آخر لا يكفي.
- إذا كان الفحص السياقي بالذكاء الاصطناعي مفعّلاً، يجب أن يصدر حكماً واضحاً لكل مقطع اعتماداً على نص التفريغ. فشل الخدمة أو نقص النص يمنع النشر التلقائي، ولا يُعامل كأنه نتيجة آمنة.
- يمكن إجراء معاينة تجريبية دون رفع. الرفع الحقيقي يرفض المقاطع التي لا تملك درجات اختيار وعنواناً موثقاً وفحصاً نهائياً ناجحاً.
- في وضع الحجب الصوتي (`censor`)، لا يُقبل المقطع إلا إذا تحقّق النظام من كتم الصوت وإخفاء الكلمات في الترجمة للمقطع نفسه؛ فشل أحدهما أو غياب سجله يمنع النشر.

## قبل YouTube

1. شغّل وضع `--autopilot` للمقاطع التي تريد نشرها تلقائياً.
2. راجع `safety_report.json` و`risk_scorecard.json` و`publish_blocklist.json`.
3. لا يكفي وجود التقريرين: يجب أن يطابقا أوقات المقطع المحدد. إذا كانت المراجعة السياقية مفعّلة، يجب أن تسجّل حكماً كاملاً لكل مقطع اعتماداً على نص التفريغ؛ النتيجة الناقصة أو الفاشلة تمنع الرفع.
4. أي مقطع فيه تحريض على الكراهية أو العنف أو نص حساس في الترجمة/OCR يبقى محظوراً أو يحتاج مراجعة يدوية.
5. ابدأ بـ `private` أو `unlisted`، ثم انشر يدوياً بعد فحص الفيديو والصوت والعنوان والوصف.
6. إذا سجّل النظام إنذار سياسة للقناة، يتوقف الرفع الآلي حتى تتم المراجعة والإقرار الصريح بالمخاطر.

## قبل TikTok

1. عند إعادة استخدام مقطع سبق نشره على منصة أخرى، يجب أن يثبت المشروع إضافة أصلية: تعليق تحليلي، تعليق صوتي، تحليل تحريري، أو B-roll ذي صلة.
2. يسجل ذلك في `project_manifest.json`، مثال:

```json
{
  "transformation": {
    "clips": {
      "0": {
        "commentary": true,
        "voiceover": false,
        "broll": false
      }
    }
  }
}
```

3. بدون هذا الدليل، يعرض النظام سبب الرفض ويضع المقطع في المراجعة بدلاً من رفع نسخة معدّلة شكلياً.
4. عند وجود الدليل، يمكن تشغيل `variant_policy=auto` لإنشاء نسخة مخصصة للمنصة، مع تسجيل `variant_of` في `publish_history.jsonl` حتى لا يعيد النظام نفس المحاولة.

## الحقوق

للمحتوى ليس من إنتاجك، أضف `rights_manifest.json` يوضح أساس الاستخدام، ورابط الترخيص/الإذن أو إقرار المالك، و`allow_publish: true`. الإذن وحده لا يحول المحتوى تلقائياً إلى محتوى أصلي أو مضمون القبول في تحقيق الدخل.

## تجهيز البيئة

- FFmpeg وFFprobe
- Tesseract مع اللغتين `ara` و`eng`
- `fpcalc` لفحص بصمة الموسيقى
- الحزمة الأساسية من `uv sync --extra dev --extra upload`
- مسار تفريغ نصي CPU اختياري: `requirements-transcribe-fallback.txt`
- WhisperX/Torch الكامل اختياري ويحتاج بيئة GPU/ذاكرة مناسبة؛ عند غيابه يستخدم التطبيق `faster-whisper` إذا كان مثبتاً.

راجع دائماً إرشادات المنصة الحالية قبل النشر؛ أدوات المشروع تقلل المخاطر ولا تمنح ضماناً بقبول الفيديو.
