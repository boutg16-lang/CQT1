# OUSSAMA Cutter 8.5.0-ultimate — منحنى الاحتفاظ

_التاريخ: 2026-11-13 · النطاق: أين يغادر المشاهد، وهل الخطاف يصمد فعلاً_

## 0. إصلاح جوهري سبق المنحنى

استعلام الأرقام المجمّع كان يبني الفلتر `video==id1;id2;id3`. في YouTube
Analytics الفاصلة المنقوطة تفصل **فلاتر مختلفة**، والقيم المتعددة تُفصل
بفاصلة: `video==id1,id2,id3`. النتيجة أن أي دفعة فيها أكثر من فيديو كانت
تُرجع صفر صفوف — الحلقة كانت تعمل فقط عندما يكون هناك فيديو واحد. أُصلح
الفلتر وأُضيف اختبار يثبت الصياغة والنتائج المتعددة.

## 1. المشكلة

8.4.0 أضاف `averageViewPercentage` — رقم واحد. لكن 80% متوسطاً قد يعني
«100% ثم هبوط حاد» أو «نزيف بطيء طوال المقطع». الرقم لا يقول **أين** يغادر
المشاهدون، ولا يفرّق بين خطاف قوي وجسم ممل.

والأسوأ: وزن «الخطاف» كان يتعلّم من **إجمالي المشاهدات**. المشاهدات يحرّكها
الموضوع والخوارزمية والعنوان، لا جودة أول 3 ثوانٍ. فكانت الحلقة تعلّم
الخطاف درساً خاطئاً.

## 2. منحنى الاحتفاظ الحقيقي

تقرير YouTube Analytics:
`dimensions=elapsedVideoTimeRatio` +
`metrics=audienceWatchRatio,relativeRetentionPerformance` + `filters=video==ID`.

يُحوَّل إلى ملخص قابل للتنفيذ:

| الحقل | المعنى |
|---|---|
| `hook_ratio` | متوسط البقاء في أول 10% — هل أمسك الخطاف؟ |
| `mid_ratio` | المنتصف (40–60%) — هل الجسم يملّ؟ |
| `end_ratio` | آخر 10% — هل النهاية تُبقي حتى النهاية؟ |
| `max_drop_at` | نسبة مكان أسرع هبوط داخل المقطع |
| `max_drop_pct` | حجم ذلك الهبوط بالنقاط |

مع تنعيم ثلاثي النقاط: ثانية ضوضاء واحدة لا تُسمّى «الانهيار».

## 3. التكلفة محسوبة

كل فيديو يحتاج استعلاماً منفصلاً. لذلك:

- `VIRALCUTTER_RETENTION_CURVES` — الحد الأقصى للمنحنيات في كل تحديث
  (افتراضي 20، و`0` يعطّل الميزة).
- كاش `retention_curves.json` داخل المشروع، صلاحية 72 ساعة
  (`VIRALCUTTER_RETENTION_TTL_HOURS`).
- فشل/حصة/OAuth لمقطع واحد لا يُسقط التقرير: بقية المقاطع تُقاس.
- المنحنى لا يُجلب إلا للفيديوهات التي رجعت لها أرقام بالفعل.

## 4. ماذا يتغيّر في الاختيار

- وزن `hook` يُتعلَّم الآن من `vs_hook_retention` عند وجوده: هل المقاطع
  الأعلى تقييماً في الخطاف تُبقي مشاهدين أكثر في أول 10%؟
- إذا لا يوجد منحنى، يرجع تلقائياً إلى `vs_views` (توافق كامل مع 8.4.0).
- كل إزاحة تحمل `signal: "hook_retention"` أو `"views"` في
  `performance_insights.json` — تعرف على أي دليل بُنيت.

## 5. التقرير

### JSON
- `retention_curve`: عدد المنحنيات، متوسطات hook/mid/end، وأسوأ مقطع
  (`max_drop_at`, `max_drop_pct`, `drop_seconds`).
- كل ارتباط خاصية يحمل `vs_hook_retention` و`hook_retention_samples`.
- كل مقطع في `clips` يحمل `metrics.retention_curve`.

### Markdown
قسم «منحنى الاحتفاظ»:
- أول 10% / المنتصف / النهاية.
- أكبر هبوط: عند 38% من المقطع (≈12.6 ثانية) بخصم 9.2 نقطة — «عنوان المقطع».
- تحذير صريح إذا كان الخطاف يخسر أكثر من 15% في أول 10%.

## 6. التشغيل

```bash
# منحنى فيديو واحد (للفحص اليدوي)
python -m scripts.analytics --retention VIDEO_ID --days 28

# الحلقة الكاملة تجلبه تلقائياً (حتى 20 منحنى/تحديث)
python -m scripts.performance_loop --project "VIRALS/my_project" --auto --force
```

## 8. حدود

- المنحنى متاح فقط بعد accumulation مشاهدات كافٍ؛ الفيديو الجديد جداً قد
  يعيد منحنى فارغاً — لا يُخترع رقم.
- `audienceWatchRatio` نسبة داخل الفيديو، لا مقارنة بين فيديوهات مختلفة الطول.
- الحصة (quota) قد تمنع بعض الاستعلامات؛ الكاش والحد الأقصى يحتوونها.
- لا يزال الارتباط ليس سببية، لكنه الآن يقيس **مكان** المشكلة لا متوسطها.
