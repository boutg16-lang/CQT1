# ملاحظات إصدار OUSSAMA Cutter 7.7.0-pro

## الفحص البصري للمحتوى الحساس

أضيفت طبقة فحص بصري محلية تعمل بعد إخراج المقاطع النهائية وقبل بوابة النشر. تستخدم الطبقة نموذج ONNX محلياً، وتضع نتيجة كل مقطع داخل `risk_scorecard.json` مع حالة النموذج وعدد الإطارات ودرجة المحتوى الرسومي.

أصبح بالإمكان التحكم في الفحص من CLI أو WebUI عبر ثلاثة أوضاع: `off` لإيقافه، `auto` للفحص عند وجود نموذج محلي، و`on` لجعل الفحص إلزامياً. كما أضيفت سياسة `warn` أو `block`، بحيث يمنع الوضع المحافظ النشر إذا كانت النتيجة مرتفعة أو إذا كان الفحص الإلزامي غير متاح.

## الدمج مع الأمان والرفع

تقرأ بوابة الرفع الآن حالة فشل الفحص البصري الإلزامي من بطاقة المخاطر، فلا يمكن تجاوز الحماية بفتح تبويب النشر مباشرة. كما تنظف بطاقة المخاطر `publish_blocklist.json` القديم عند نجاح إعادة الفحص بدون عناصر محجوبة، منعاً لبقاء قرار قديم يؤثر في مشروع نظيف.

يظهر في تقرير HTML تنبيه صريح يوضح هل تم تنفيذ الفحص البصري، أو استمر التقرير بدون نموذج، أو أُوقف النشر بسبب فشل الفحص الإلزامي.

## WebUI

أضيفت لوحة عربية داخل قسم الأمان تسمح بتحديد وضع الفحص، سياسة القرار، عدد الإطارات، مسار نموذج ONNX، وخيار التنزيل الاختياري. تُحفظ الإعدادات تلقائياً وتنتقل إلى التشغيل الفردي وإعادة الرندر والطابور.

## حدود مهمة

النموذج الحالي المدمج اختيارياً موجه للمحتوى الجنسي/العري والمحتوى الرسومي، وليس كاشفاً شاملاً للعنف أو الكراهية أو السياق. لذلك يجب إبقاء فلتر النص والدلالات والمراجعة البشرية مفعلة قبل النشر العام. لا يقدم الفحص ضماناً لقبول YouTube؛ إنه طبقة تقليل مخاطر.
