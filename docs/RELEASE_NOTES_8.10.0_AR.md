# OUSSAMA Cutter 8.10.0-ultimate — تحديث المصدر بأمان

_التاريخ: 2026-11-14 · النطاق: تحديث نسخة D:\OS من GitHub_

## 1. المشكلة

كل مرة تُصلح فيها المشروع، تبقى نسخة `D:\OS` على إصدار قديم حتى تنفّذ
`git pull` يدوياً. النتيجة: نفس العطل يظهر من نسخة قديمة، وتضيع إصلاحات
كثيرة.

## 2. الحل

### أ. سكربت واحد
```powershell
cd D:\OS
.\update_project.bat
```

يفعل:
1. `git fetch origin main`
2. يقارن `HEAD` بـ`origin/main`
3. إن كان متأخراً: `git pull --ff-only origin main`
4. يطبع الملفات المتغيرة
5. إن تغيّرت ملفات التبعيات: ينبهك لتشغيل `setup_on_d.ps1`
6. يطلب إعادة تشغيل التطبيق

### ب. أمان صريح
- يرفض التحديث إذا كانت هناك **تعديلات متتبعة** غير محفوظة
  (`dirty_worktree`) — لا يخفي عملك.
- يرفض `diverged` إذا كان `main` المحلي متقدماً؛ لا يعمل `reset`.
- لا يعمل merge؛ فقط fast-forward.
- لا يشغّل التثبيت تلقائياً؛ يخبرك بالأمر الصحيح.

### ج. فحص بلا تعديل
```powershell
.\update_project.bat --check
.\.venv\Scripts\python.exe -m scripts.source_updater --check --json
```

رموز الخروج:
- `0`: محدّث أو تم التحديث.
- `2`: رفض (تعديلات محلية/تباعد/فشل pull).
- `3`: يوجد تحديث (وضع `--check`).

## 3. التثبيت المعبأ
هذا للمصدر (`D:\OS`). نسخة الـEXE تستخدم `scripts.auto_updater.py`
والتحديثات الموقعة، لا هذا السكربت.

## 4. التحقق

- `tests/test_source_updater.py` — 5 اختبارات:
  - ليس مستودع git.
  - محدّث بالكامل.
  - متأخر مع تغيّر تبعيات.
  - رفض الشجرة الملخبطة.
  - fast-forward ناجح مع إعادة قراءة HEAD.
- المجموعة كاملة خضراء، `ruff` نظيف.

## 5. حدود

- يحتاج `git` مثبتاً و`.git` موجوداً. إن كانت نسختك حزمة تنزيل، نزّل
  الإصدار الجديد يدوياً.
- لا يحلّ تعارضات: إن كان لديك commit محلي متقدم، ادمجه/ارفعه أولاً.
- لا يثبّت التبعيات تلقائياً؛ هذا قرار واعٍ لأن `setup` قد يعيد تنزيل
  Torch أو حزم كبيرة.
