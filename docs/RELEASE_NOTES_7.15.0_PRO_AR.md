# ملاحظات إصدار OUSSAMA Cutter 7.15.0-pro

## إصلاح تكرار المقاطع

تعالج هذه النسخة الحالة التي كانت فيها عدة مقاطع تحمل عناوين مختلفة لكنها تشير إلى نافذة المصدر نفسها. أصبح `process_segments` يستخدم `start_time` و`end_time` الرقميين كمصدر حقيقة عندما يرسلهما نموذج الذكاء الاصطناعي، بدلاً من استبدالهما بمطابقة نصية أو backtrack قديم. كما أضيفت بصمة مستقرة لنافذة المصدر وdeduplication أقوى يحافظ على المرشح الأعلى تقييماً.

يُطبّق التنظيف أيضاً على القوائم القديمة أو المعدلة يدوياً قبل القص وقبل `content_guard`. لذلك لا تمر نافذة مكررة بعنوان جديد إلى مجلد `cuts` أو إلى رفع YouTube. عند إعادة إنشاء قائمة المقاطع تُحفظ القائمة الجديدة فوق القديمة صراحةً، ولا يعتمد النظام على ملف `viral_segments.txt` قديم بصمت.

## إصلاح تتبع المتحدث والوجه

أصبح `ActiveSpeakerSelector` هو صاحب القرار النهائي في اختيار الوجه عندما يكون التركيز على المتحدث مفعلاً؛ لا يعيد المسار اللاحق ترتيب الوجه حسب المساحة أو المسافة بطريقة تلغي اختيار المتحدث. أضيف حساب Mouth Aspect Ratio احتياطي لـInsightFace 106 landmarks عندما لا يتوفر 68-landmark، مع بقاء التنعيم والهسترة لمنع القفز بين الوجوه بسبب إطار واحد.

الواجهة تجعل **Focus on Active Speaker** مفعلاً افتراضياً ضمن إعداد InsightFace، وتوضح أن MediaPipe/Haar يستطيعان تثبيت الوجه فقط ولا يقدمان active-speaker حقيقياً. ينشئ المسار `tracking_report.json` ويحدد backend الفعلي، وهل طُبق active speaker أم استُخدم fallback. يظهر هذا الملخص أيضاً في `project_report`.

## الأمان والتوافق

تبقى بوابات YouTube وDry Run ومنع التكرار وقاطع القناة كما هي. هذه الإصلاحات لا تتجاوز سياسات YouTube ولا تضمن قبول المحتوى؛ يجب مراجعة الفيديو وحقوق نشره قبل الرفع الحقيقي.

## التحقق

يجب تشغيل `pytest -q` و`ruff check .` و`python -m compileall -q .` قبل التسليم. لا تشمل الاختبارات تسجيل دخول Google أو رفعاً حقيقياً أو اختبار CUDA على Windows؛ يُنفذ ذلك اختيارياً على جهاز المستخدم وفق قائمة قبول Windows.
